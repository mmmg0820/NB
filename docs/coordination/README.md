# 샤로먕 업무 운영 및 인수인계

이 문서는 샤로먕 Android 앱을 다른 담당자가 인수해도 현재 상태를 재현하고, 수정부터 검수와 배포까지 마무리할 수 있도록 업무 경계와 진행 순서를 정의한다.

- 기준 태그: `v0.1-dev-20260911-r2`

이전 태그 `v0.1-dev-20260911`과 APK SHA `89d40ac0...`는 사주 결과의 기술 메타데이터 노출 문제로 대체됐다. 이력은 삭제하지 않는다.

공유 Kotlin 파일은 Android 통합 담당만 최종 수정한다. 각 기능 담당은 패치, 테스트, 인계 문서를 제출하고 Android 담당이 충돌을 정리한다. GitHub 푸시는 DevOps 한 명만 수행한다.

## 작업 순서

1. GitHub 기준 커밋과 APK SHA를 확인한다.
2. 이슈를 기능 영역에 배정하고 담당 파일과 수용 기준을 기록한다.
3. 담당 팀은 격리된 작업 공간에서 수정·단위 테스트·인계 문서를 만든다.
4. Android 통합 담당이 정본에 반영하고 전체 테스트를 실행한다.
5. 소스 변경을 중단하고 소스 스냅샷·manifest·APK·서명 SHA를 생성한다.
6. QA는 그 APK를 전용 기기에 설치하고 설치된 APK SHA가 같은지 확인한다.
7. 기능·화면·접근성·로그를 검수하고 PASS 또는 정확한 실패 원인을 기록한다.
8. DevOps는 PASS된 동결본만 새 커밋과 태그로 게시한다.
9. 게시 후 원격 저장소를 다시 내려받아 APK SHA와 제외 자산을 재검증한다.
10. 모든 문서와 비공개 작업 산출물을 뽀그리 보관소에 동기화한다.

## 완료 정의

- 요청 동작과 승인 화면이 정본 소스에 반영됐다.
- 관련 단위 테스트와 전체 테스트가 통과했다.
- APK, 설치된 base APK, 문서에 적힌 SHA가 일치한다.
- QA 증거에는 기기, Android 버전, 해상도, density, fontScale, theme, focus가 기록됐다.
- 치명적 오류와 ANR은 MTJ 앱 프로세스 기준으로 확인했다.
- 배포 권한이 확인되지 않은 디자인 원본과 카드 자산은 소스와 APK에 없다.
- GitHub README, 기능 문서, QA 보고서, 릴리스 문서가 현재 커밋을 가리킨다.
- 이전 실패 릴리스는 삭제하지 않고 대체 관계를 표시했다.

## 새 담당자의 첫날

1. 루트 README와 `docs/`의 영역별 README를 읽는다.
2. 기준 태그를 체크아웃하고 APK SHA를 재계산한다.
3. Android 빌드 환경과 디버그 서명 조건을 확인한다.
4. 본인 영역의 소유 파일, 테스트, 미완료 목록을 확인한다.
5. 변경 전 DevOps와 브랜치·태그 이름을 정하고 Android 통합 담당에게 공유 파일 소유권을 확인한다.
6. 검수 없이 기존 증거를 새 APK에 재사용하지 않는다.

## 현재 후속 업무

- 스토어 출시용 서명과 release 빌드 파이프라인
- 320/360/411/600dp 및 fontScale 1/1.5/2 전체 회귀
- TalkBack, 키보드 포커스, reduced motion 검수
- 카드 자산의 배포 권한과 출처 문서 확정
- 실제 사주 계산 결과의 도메인 전문가 검증 확대
- 결제·구독·네트워크·복구·마이그레이션을 포함한 전체 제품 인증
